# v1.0.0 验证结果

验证日期：2026-10-25。样机环境：Windows 10 Pro 22H2 build 19045、x64、12 个逻辑处理器，.NET SDK 10.0.103 / 运行时 10.0.3。

## 已完成的验证

| 项目 | 结果 |
|---|---|
| Release 构建 | 0 错误、0 警告 |
| 便携发布 | Windows x64 自包含目录，包内带运行时 |
| 自动回归 | 50 项通过：协议字段校验、错误响应拒绝、标定换算、刷新调度、配置保存、缓存恢复、圆环绘制及进程清理 |
| K7 Ultra | 接收器 `3837:1001`，逻辑身份 `3837:4150`；实测 93%，与官方软件一致 |
| ROG RX TKL | 接收器 `0B05:1A07`，厂商接口 `MI_01 / FF00:0001`；多次读到 96%，未充电 |
| HID 枚举 | 样机列出 31 个接口，包括受保护接口的访问错误 |
| 通知区图标 | 两枚图标均能在真实 Windows Shell 注册并取得位置，覆盖可见区及折叠区位置返回 |
| 单实例 | 重复启动通过 IPC 前置面板，没有新增常驻实例 |
| 跨进程缓存 | 独立新进程恢复鼠标 93%、键盘 96% 及各自原时间，标记为上次读数，不重新查询或改写时间 |
| 失败时显示 | 断链、超时和连续失败保留旧值；首次没有读数时保持未知；恢复成功才替换 |
| 缓存边界 | 60 天旧缓存保留、0% 有效、损坏文件容错、绑定变化隔离、只有最新两条、无临时文件残留 |
| 退出清理 | 覆盖正常退出、查询取消、超时、关闭 Job，以及父进程直接结束后的 worker 清理 |
| 绿色圆环 | 16px / 24px 浅深背景预览；绿色像素随电量减少，低电量仍为绿色 |
| 无运行日志 | 正常模式仅保存设置与最新快照，没有文件日志器或自动报文转储 |

开发阶段一次约 119.8 秒的静置测量中，CPU 时间增量为 0 秒（受系统计时精度限制）。工作集样本约 80.8–114 MB，私有内存样本约 57.9 MB。这些是样机观察值，不是固定资源上限。

## 可复验步骤

1. 唤醒两台设备，关闭其他探测程序后运行 `--probe --summary`，与官方软件对照。
2. 将右下角两个图标设为常显，检查绿色圆环、左键单台刷新、右键打开面板并刷新两台、悬停不刷新。
3. 将定时刷新暂设为 1 分钟检查调度，再恢复默认每天一次；另测活动模式静置 5 分钟后的单次刷新。
4. 成功读取后断开接收器，确认电量与原时间保留，错误状态明确；重连后手动刷新恢复。
5. 退出再启动，确认先恢复两台缓存，失败不清空，成功后替换。
6. 开启自启后重新登录，确认仅托盘驻留；再次启动不重复创建图标。
7. 在探测中退出，检查全部所属进程已结束。
8. 在 Windows 11、高 DPI 和多显示器环境重复上述操作并补记结果。

## 开发验证命令

```powershell
& .\bin\Release\net10.0-windows\PeripheralBattery.exe --self-test | Out-String
& .\bin\Release\net10.0-windows\PeripheralBattery.exe --probe --summary | Out-String
```

- `--tray-self-test`：临时注册两枚通知区图标、读取位置后移除。不要与同一目录下正在运行的正式实例同时执行。
- `--cache-inspect`：只读恢复已有缓存并输出电量、原时间及旧读数状态，不发送 HID 查询。
- `--test-session`：测试会话，不保存用户设置、缓存或登记自启。
- `--render-preview <目录>`：用当时真实读数生成面板浅深色图片；没有有效读数时显示未知。
- `--render-notification-icons <目录>`：生成明确标注示例值的通知区图标预览。
