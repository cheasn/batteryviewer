# v1.0.0 HID 协议与身份

## ROG Strix Scope RX TKL Wireless Deluxe

* 验证样机接收器：`0B05:1A07`，厂商接口 `MI_01`，Usage `FF00:0001`，Input/Output各65字节，无 Feature Report。
* 写入 Windows Output Report：`00 12 01`，补零至接口的 OutputReportByteLength。首字节00是无编号报告占位。
* 有超时地读取 Input 流，忽略其他响应，只接受 `12 01` 协议响应；Windows保留首字节00时先规范化。
* 规范化后 payload[5] 为0–100百分比，[8]为充电0/1；[10]为重复电量字段。非匹配报文、短报文或非法字段不显示电量。
* 样机多次查询读到96%、未充电；原始协议读取已验证，官方软件对照与充电切换仍待完成。

## MCHOSE K7 Ultra

* 验证样机同时枚举 `3837:1001` 与 `5253:1021`，产品描述均为 `MCHOSE K7 Ultra`。首版使用 `MI_02` 的 `FF01:0001` 厂商集合，不使用 `FF0B:0104` 作为电量通道。
* 官方 M HUB 型号表将 K7 Ultra 对应逻辑PID十进制16720，即 `4150`。样机在 `3837:1001` 接口的状态响应中确认逻辑身份 `3837:4150`。
* Feature Report ID `11`，20字节负载：命令`06`加零填充；所有负载字节逐字节异或`FF`，Report ID不反相。Windows API传输缓冲区补至Feature最大长度。
* 状态查询保持同一打开句柄，短等待后最多6次读取；通过重叠 `IOCTL_HID_GET_FEATURE` 获取实际长度，再校验ID、命令、逻辑VID/PID、电量范围和充电字段。
* 去除ID、反相后的payload：命令[0]；VID小端[1..2]；PID小端[3..4]；固件[5..8]；标志[9]；电量[10]；充电[11]。
* 已验证响应样例：`11 F9 C8 C7 AF BE E3 FA FD FA F6 A2 FF A2 FF FF FF FF FF FF FF`，解码电量93%、充电0，与官方软件读数一致。该报文加入自动回归测试。
* 同时连接的 `5253:1021` 在本次环境下未返回有效鼠标状态，不能据此认定协议完全不支持；不会从无效缓存显示电量。

## 共同规则

日常模式只查询目标厂商接口。未识别逻辑身份不会被命名为K7。多台不同目标设备时拒绝自动选择，要求调试绑定。手动标定必须通过响应匹配和数值范围校验，保存时需成功测试并人工核对。使用完整接口路径绑定的标定在换USB端口后可能需要重绑。

系统设备移除与查询失败分开处理。Windows 通用输入消息不能证明射频外设真实睡醒，当前活动模式仅做静默后的首次输入判断。
